## 3. Create actual geometric questions

Every question must visually contain two parts:

## 4. Geometry generation and mathematical correctness

This is the most important engineering requirement.

Do not create random SVG shapes and assume that they form a valid puzzle. The geometry must be mathematically consistent and independently verifiable.

### Recommended construction approach

Use deterministic polygon geometry rather than manually drawing shapes without a validation method.

A recommended approach is:

1. Define a target polygon or composite target shape.
2. Partition that target into smaller polygonal pieces with known coordinates.
3. Preserve each piece's exact geometry.
4. Shuffle the pieces and rotate some pieces to generate the source arrangement.
5. Generate the correct target figure from the original complete shape.
6. Generate four plausible target shapes in total, including the correct one and three distractors.
7. Validate that the pieces can be assembled to form the correct target without gaps, overlap, or mirroring.
8. Verify that none of the other four choices is also a valid assembly, including option E's meaning.

For polygonal puzzles, prefer integer-grid or rational-coordinate geometry wherever possible. This makes area checks, rotations, shared edges, and exact-cover validation more reliable.

You may use a different construction method if it provides equally strong verification.

### Required assembly rules

When testing whether pieces fit a target:

- Allow rotations by the angles supported by the puzzle's geometric construction.
- Do not permit reflection or mirroring.
- Do not scale or independently resize individual pieces.
- Preserve relative piece dimensions.
- Do not allow pieces to overlap.
- Do not permit gaps or missing area.
- Use each piece exactly once.
- Allow the assembled target to be displayed at a different overall scale if needed, while preserving all relative proportions.

Do not assume that equal total area alone proves that a target is constructible. Area is a useful consistency check, not sufficient proof of a valid tiling.

### Distractor validation

Create distractors that preserve reasonable visual plausibility while differing in geometry.

Use automated checks where possible, including:

- Total area consistency.
- Polygon boundaries and edge lengths.
- Shape and angle constraints.
- Rotation-only congruence.
- Partition and tiling validity.
- Exact-cover or equivalent search for the supported geometric model.

If complete geometric verification is not possible with the current architecture, simplify the geometric model rather than presenting unverified puzzles as correct.

**Never publish a question unless its answer key has been independently validated.**

## 5. Visual implementation

Prefer programmatically generated SVG because it provides scalable, crisp geometric figures and can represent exact polygon coordinates.

Every figure should render correctly at different viewport widths and on high-density displays.

Requirements:

- Use clear outlines and restrained, consistent fill colors.
- Give pieces enough spacing so their boundaries remain distinguishable.
- Maintain consistent visual scale within each question.
- Keep source pieces and answer figures visually separated.
- Label options A–D clearly.
- Make the E option accessible and selectable like the other answer options.
- Avoid unnecessary gradients, shadows, glassmorphism effects, animations, or decorative graphics that interfere with geometric interpretation.
- Prevent clipping, distorted proportions, accidental overlaps, and blurry rendering.
- Do not use raster AI-generated illustrations as the authoritative geometry unless their exact shapes can be validated independently.

Prefer separate SVG components or reusable geometry-rendering utilities rather than one enormous component containing all 15 questions.
